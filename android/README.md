# DocSync AI for Android (Play Store)

The Android app is a [Trusted Web Activity](https://developer.chrome.com/docs/android/trusted-web-activity):
the production site running full screen in Chrome, with its own icon and Play Store listing. There is
no second codebase. Every web deploy updates the app, and Google sign-in works as it does in Chrome.

- Package: `tech.analogdigital.docsync`
- Site: `https://docsync.analogdigital.tech` (production only; staging never claims the app)
- Configuration: [`twa-manifest.json`](twa-manifest.json). The Android project itself is generated by
  [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) and not committed.
- Site ↔ app link: [`core/android.ts`](../core/android.ts), served at `/.well-known/assetlinks.json`.

## Signing key

The upload key lives outside the repo, in `~/.docsync-android/` on the release machine:

- `upload-key.jks`: the keystore (alias `upload`). `android/upload-key.jks` is a symlink to it.
- `passwords.env`: `BUBBLEWRAP_KEYSTORE_PASSWORD` and `BUBBLEWRAP_KEY_PASSWORD`.

Back both up (a password manager is fine). With Play App Signing, a lost upload key can be reset
through Play support, but that takes days.

To print the key's public fingerprint, as listed in `core/android.ts`:

```sh
set -a; . ~/.docsync-android/passwords.env; set +a
keytool -list -v -keystore ~/.docsync-android/upload-key.jks -alias upload \
  -storepass "$BUBBLEWRAP_KEYSTORE_PASSWORD" | grep SHA256
```

## Build

Needs JDK 17 or later and the Android SDK, set in `~/.bubblewrap/config.json`
(`{"jdkPath": "…", "androidSdkPath": "…"}`).

```sh
cd android
npx @bubblewrap/cli@1.27.0 update --skipVersionUpgrade   # (re)generate the project from twa-manifest.json
set -a; . ~/.docsync-android/passwords.env; set +a
npx @bubblewrap/cli@1.27.0 build --skipPwaValidation     # app-release-bundle.aab + app-release-signed.apk
```

For a new release, raise `appVersionCode` (by 1) and `appVersionName` in `twa-manifest.json` first. Play
refuses an upload whose version code it has seen.

## Check on a phone

1. Install `app-release-signed.apk` (USB with `adb install`, or copy it to the phone).
2. Open DocSync. It should open full screen, with no address bar. If Chrome's address bar shows,
   Android couldn't verify the link: check that `https://docsync.analogdigital.tech/.well-known/assetlinks.json`
   lists the fingerprint of the key that signed this build.
3. Sign in with Google and scan the sample document.

## Publish on Play

1. In [Play Console](https://play.google.com/console) (one-time $25 developer account), create the app
   "DocSync AI", with free pricing and the Business category.
2. **Test and release → Testing → Internal testing**: upload `app-release-bundle.aab` and accept Play
   App Signing.
3. **Test and release → App integrity**: copy the **app signing key** SHA-256 fingerprint into
   `core/android.ts`, next to the upload key, and deploy the site. Builds from Play are signed with that
   key, and without it they open with an address bar.
4. Fill in the store listing (screenshots, short and full description in English and Hindi), the
   content rating, the target audience (adults), and **Data safety**:
   - collected: email and name (Google sign-in), photos and voice notes (to read documents)
   - shared: with the AI providers that read them, and with the user's own Google Sheets, Drive and Notion
   - encrypted in transit
   - privacy policy: `https://docsync.analogdigital.tech/privacy`
5. Promote from internal testing to production once testers have checked it.
